# 개발 가이드

[English](DEVELOPMENT.md) | 한국어 · [프로젝트 개요](../README.kr.md)

## 빌드 환경

JDK 17을 사용합니다. Minecraft 1.20.1, Forge 47.4.10을 대상으로 하며 Gradle 8.8 wrapper를 사용합니다.

```bash
./gradlew build
```

Windows에서는 `./gradlew` 대신 `.\gradlew.bat`를 사용합니다.

실행용 파일은 `build/libs/slimic-1.20.1-<버전>.jar`입니다. `-sources.jar`는 개발용 산출물입니다.

## 개발 명령

| 명령 | 용도 |
| --- | --- |
| `./gradlew runClient` | 개발용 클라이언트를 실행합니다. |
| `./gradlew runServer` | 로컬 개발 서버를 실행합니다. |
| `./gradlew runGameTestServer` | 전용 Forge GameTest 서버를 실행합니다. |
| `./gradlew runData` | 설정된 데이터 생성기를 실행합니다. |
| `./gradlew verifyGuidebook` | 한·영 안내서 리소스·링크·조합법·선택 조건을 검사합니다. |

GameTest는 일반 개발 월드인 `run`과 분리된 `build/game-test-server`에서 실행됩니다. 테스트 소스와 구조는 `src/gameTest`에 두며 배포용 산출물에 포함하지 않습니다. 빌드는 테스트 코드를 컴파일하고, `runGameTestServer`가 실제 테스트를 실행합니다.

## 소스 구조

- `src/main/java`: 모드 진입점, 등록 코드, 슬라임 동작, 아이템 상호작용, 클라이언트 렌더링
- `src/main/resources`: 메타데이터, 텍스처, 번역, 조합법, 전리품 정의
- `src/generated/resources`: 필요한 경우 생성하는 배포용 리소스
- `src/gameTest`: 개발 전용 테스트 모드, 테스트 코드, 구조
- `docs`: 한글·영문 상세 게임플레이 및 개발 문서

각 README에는 프로젝트 개요와 문서 링크만 둡니다. 상세 가이드는 한글·영문 쌍으로 함께 관리합니다.

`src/main/resources`에는 실제 모드에서 사용하는 에셋만 포함합니다. 참고 자료와 검증 산출물은 배포 리소스와 분리합니다.

## 버전과 변경 관리

초기 개발 버전은 `0.3.x` 범위에서 패치 단위로 배포합니다. `gradle.properties`의 `mod_version`과 [변경 기록](../CHANGELOG.md)을 함께 갱신하며, 빌드에서 해당 변경 기록의 존재를 확인합니다.

배포 버전을 바꿀 때 개발 전용 테스트 모드의 버전도 맞춥니다.

## 슬라임 회수 데이터

`FriendlySlimeInteractions`는 Forge 엔티티 상호작용 이벤트에서 황금 사과 먹이 주기를 처리합니다. 살아 있고 제거되지 않은 크기 1의 `minecraft:slime`만 대상입니다. 서버에서 플레이어 소유의 대기 중인 동료 한 마리를 만들고 기존 이름을 유지합니다. 엔티티 추가에 성공한 경우에만 야생 슬라임을 제거하고 서바이벌의 황금 사과를 소모합니다. 상호작용이나 소환이 취소되면 두 대상 모두 보존하며, 전환 후에는 공통 동료 회수 규칙을 적용합니다.

회수 아이템의 `SlimeData`에 Forge 영구 데이터와 capability를 포함한 슬라임의 직렬화 상태 전체를 보관합니다. 새 영구 특성은 엔티티의 표준 저장·불러오기 훅을 사용해야 회수 과정에서도 자동으로 보존됩니다.

복원 시 원래 UUID와 소유권을 유지합니다. 아이템 재배치와 부활은 대기로 시작하며 일반 월드 로드는 저장된 명령을 유지합니다. 새 소환 위치에 맞춰 좌표, 이동 속도와 낙하 거리를 대체하며, 끈과 탑승 관계는 복원하지 않습니다. 같은 UUID의 개체가 이미 로드되어 있으면 그 저장 아이템의 재소환을 막습니다.

엔티티 추가가 끝날 때까지 소환 개체는 임시 상태입니다. 생성 콜백 이후에도 살아 있고 올바른 월드에 등록되어 있으며 원래 UUID와 주인을 유지하는지 확인한 뒤 소환 아이템을 소비합니다. 고정된 엔더 슬라임의 거점 개수도 콜백 이후에 다시 검사해 중첩 복원으로 주인별 제한을 넘지 않게 합니다. 임시 개체는 동료 명부를 갱신하지 않으며, 죽어도 별도 회수 코어를 만들지 않습니다. 추가 도중 제거된 개체를 포함해 실패한 개체의 등록을 정리하고, 아이템 데이터와 이전 명부 기록은 그대로 남겨 재시도할 수 있게 합니다. 회귀 검사는 새·저장 아이템의 제거, 사망, 주인·UUID 변경, 사망을 동반한 생성 취소와 경쟁하는 엔더 복원을 포함합니다.

회수 아이템의 겹침 제한은 1개입니다. 크리에이티브의 기본 아이템 수량 복원 경로에서도 회수 아이템은 재소환 시 소모합니다. 새로 제작한 아이템은 기존처럼 크리에이티브에서 반복 사용할 수 있습니다.

## 검증

[동료 간 상호작용 검증](INTERACTIONS.kr.md)은 직업 간 협력과 소유권·수량·장비 보존 규칙을 정리합니다.

변경을 마무리하기 전에 모든 Java 소스에 Google Java Format을 적용합니다. 1.37 버전의 포매터는 Java 21에서 실행하며, 모드의 컴파일 대상과 실행 환경은 Java 17을 유지합니다.

게임플레이를 변경한 뒤에는 `build`와 `runGameTestServer`를 실행합니다. 조합법, 기본 소환, 회수·재소환, 생명력과 다른 특성, 소유권, 가득 찬 인벤토리, 막힌 위치, 크리에이티브 사용, 저장, 따라오기와 사망 동작을 검증합니다.

테스트 구조는 마커보다 한 칸 위에 배치되므로 구조의 바닥은 상대 Y=1입니다. 테스트용 구조는 배포용 에셋과 분리해 유지합니다. 작업 구역 준비 중에는 서버의 청크 작업 큐를 처리하여 강제 로드한 모든 청크가 엔티티 틱을 지원하는지 확인합니다. 준비 대기는 실제 시간 30초로 제한하며, 개별 동작 검사의 틱 제한은 유지합니다.

## 능력치·채굴·JEI 연동

공통 능력치 단계는 엔티티 데이터로 동기화합니다. 서버의 메뉴 검증에서 소유권·거리·사용 가능 포인트·강화 한도를 확인합니다. 이름 변경 패킷은 발신자가 현재 연 슬라임 메뉴에만 적용합니다. 생명력 강화는 현재 생명력을 회복하지 않고 최대치만 바꿉니다.

메뉴 열기 데이터에 슬라임 종류를 포함해 클라이언트에서 개체가 사라져도 화면을 닫을 때까지 정확한 슬롯 구성을 유지합니다. 네트워크 프로토콜 16은 서로 호환되는 클라이언트와 서버 빌드를 요구합니다. 숨겨진 가방 페이지로의 이동을 거부하고 적재량이 바뀌면 현재 페이지를 보정합니다. 기존 아이템 묶음의 수량 변경도 가방에 통지하여 부분 하역 후 채굴을 재개합니다.

관리 화면의 장비·가방·플레이어 보관함·핫바는 `SlimeMenu`의 공통 배치 상수를 사용해 같은 열 시작점과 간격에 맞춥니다. 가방은 9열·3행 페이지이며 미해금 칸은 어두운 자리 표시로만 그리고 아이템 이전은 허용하지 않습니다. 한 페이지뿐이면 페이지 버튼을 숨기고 전투 대상 설정에서는 가방 격자를 숨깁니다.

채굴 상태·가방·기력·활동 진행도는 표준 엔티티 저장·불러오기 훅을 사용합니다. 장착 곡괭이와 삽은 각각 기본 손과 보조 손 장비 칸을 사용해 클라이언트 렌더링과 아이템 내구도를 동기화합니다. 한 틱에 최대 블록 하나를 채굴하고, 한 번의 탐색에서 검사하는 위치 수를 제한하며, 대상 탐색을 위해 이웃 청크를 로드하지 않습니다.

조합 직렬화기는 친근한 슬라임의 저장 특성과 정확한 곡괭이 스택을 결과에 복사합니다. JEI API는 컴파일 전용 의존성이며 개발 실행 시 연동은 선택할 수 있습니다. JEI 없는 동작은 `./gradlew runClient -PenableJei=false` 또는 `./gradlew runGameTestServer -PenableJei=false`로 검증합니다. 공통 게임 로직에서는 JEI나 클라이언트 클래스를 참조하지 않습니다.

## 운반과 보관

`BagSlime`은 작업 특화 사이에서 적재량에 따른 가방 제한, 쓰러질 때 보존, 저장·불러오기와 회수를 공유합니다. 채굴은 기존 저장 호환성을 위해 `MiningBag` NBT 키를 유지하며, 운반은 최대 54칸의 `TransportBag`을 사용합니다. 운반 가방은 공통 기본값과 매 강화 증가량을 모두 2배로 계산합니다. 관리 메뉴에는 장비 칸이 없고 현재 가방 페이지를 서버에서 검사합니다.

운반 작업은 소환 위치 중심의 탐지 구역에서 로드된 청크의 슬라임 상자와 같은 주인 또는 상호 공동 소유 관계의 작업 동료를 찾습니다. 서버 스레드에서 수용량을 미리 계산한 뒤 아이템을 이동합니다. 전달 직전에 요청을 재검사하므로 여러 운반 슬라임이 도구를 복제하거나 이미 보급된 장비를 덮어쓰지 않습니다. 이동 대상은 임시 상태이며 화물과 명령은 저장하므로, 불러오기나 재소환 후 중단된 작업을 다시 선택할 수 있습니다.

슬라임 상자는 표준 27칸 보관함 메뉴와 Forge 아이템 capability를 사용하며, 일반 인벤토리 저장·잠금·비교기 갱신·상자와 내용물의 개별 드롭을 지원합니다. 일반 상자는 물류 대상에서 제외합니다.

검증 범위는 모든 적재량 단계, 가방 두 페이지, 소유권, 가득 찬 상자와 부분 적재, 동시 도구 보급, 도구 데이터와 고장, 채굴 재개, 상자 저장·자동화·드롭과 운반 슬라임 회수를 포함합니다. 클라이언트에서는 두 특화의 화면, 페이지 동기화, 상자 메뉴, 모델 리소스와 선택적 JEI 조합을 확인합니다.

## 굴착·조작기·파발 저장 데이터

채굴 장비는 기본 손의 곡괭이와 보조 손의 삽을 사용합니다. `MiningQuarry`는 청크의 진입 높이와 현재 층을 저장합니다. 아이템으로 같은 청크에 놓으면 계획을 유지하고, 다른 청크에 놓으면 새 계획을 만듭니다. 두 경우 모두 대기하며 명시적인 채굴 명령으로 시작합니다. 아이템을 거치지 않는 작업 중 차원 이동은 기존 명령을 유지합니다. 외곽 계단은 폭 2칸의 완전한 블록 발판과 평평한 모서리를 보존합니다. 보강 재료는 `slimic:quarry_supports`에서 소비하며 설치 이벤트를 따릅니다. 탐색은 층당 256개 좌표와 갱신당 제한된 수의 빈 층으로 한정됩니다.

염색 ID와 사용자 정의 작업 능력치는 동기화된 엔티티 데이터로 관리합니다. 기본 속성을 조정할 때 속성 보정은 유지합니다. 크리에이티브 전용 조작기는 적용 전에 서버에서 활성 메뉴, 장비, 차원, 거리, 유한한 숫자와 범위, 줄어드는 가방 칸의 점유 상태를 검증합니다.

파발 조합법은 원본 폭죽 스택을 저장합니다. 신호는 피해 억제 표식이 있는 기본 폭죽 엔티티를 사용합니다. 작업자는 연속 작업 불능 시간과 상태 식별자를, 파발은 경고 기록과 재사용 대기 시간을 저장하여 회수 후 감시 명령을 다시 선택하면 기존 경고 기록과 남은 반복 대기 시간을 이어갑니다. 서버 설정은 기본 지연 시간을 제공합니다.

클라이언트는 원본 슬라임 텍스처의 밝기를 유지하는 염색 셰이더를 적용하며 장비 색은 유지합니다. 선택적 JEI 미리보기는 모든 특화를 포함합니다. 전용 서버 테스트와 함께 셰이더 로딩, 번역 화면, 조작기 패킷, 크리에이티브 기본값, 두 도구 칸을 JEI 활성·비활성 환경에서 확인합니다.

채굴 경로 탐색은 이미 로드된 작업 청크 안에서 최대 4,096개 노드와 128블록의 경로 예산을 사용합니다. 경로 예산은 탐지 범위와 별개이며 실제 도구 동작에는 도달 거리와 시야 검사를 적용합니다. 실제 몸체 아래 받침을 확인하여 유효한 작업 위치 후보를 함께 탐색합니다. 점프 중에는 유효한 경로를 유지하고, 경유 지점의 도착 오차를 줄여 계단 모서리에 걸리는 일을 방지합니다. 이동하면 정체 타이머를 초기화하며, 실패한 계단 보수 경로는 짧은 대기 후 재시도합니다. 기본 능력치의 계단 탐색, 벽 우회, 보수 접근 불가 및 장애물 제거 후 재개를 회귀 검사합니다.

`QuarryStaircaseData`는 차원별 `slimic_quarry_staircases.dat`에 계단 배치를 저장합니다. 작업 청크마다 공통 기준과 최대 28개의 상단 높이만 보관하며, 보호 조회는 청크를 불러오지 않는 상수 시간 연산입니다. 아직 첫 발판 층에 도달하지 않은 계획은 시작 높이와 진행 층을 유지하면서 공통 기준을 사용합니다. 진행된 기존 계획은 원래 배치를 유지하고 작업 전에 보호 정보를 병합합니다. 처음 소환해 대기 중인 개체는 작업 구역을 등록하지 않습니다. 이전 엔티티 데이터에 `MiningQuarry.RampOrigin`이 없으면 `TopFloor`에서 기준을 복원합니다. 보호 정보는 개체가 없어져도 남습니다. 차원 이동 후에는 소환 처리로 목적지 작업 구역을 초기화하기 전까지 이전 차원의 작업 기록을 등록하지 않습니다. 실제 파괴 직전에는 Forge 콜백 이후의 보호 상태를 다시 확인합니다. 보수 시 다른 보호 발판 위 두 칸의 통로를 보존합니다. 공통 동료 스키마는 1, 네트워크 프로토콜은 16을 유지합니다.

## Patchouli 안내서

개발 실행은 Patchouli `1.20.1-84.1-FORGE`를 선택적 런타임 의존성으로 사용합니다. `-PenablePatchouli=false`로 제외하며, `-PenableJei=false`와 독립적으로 조합할 수 있습니다. 일반 게임 로직에는 Patchouli Java API 의존성이 없습니다. 배포 JAR은 라이브러리를 포함하지 않습니다.

책 정의는 `data/slimic/patchouli_books/guide/book.json`, 본문은 `assets/slimic/patchouli_books/guide/{en_us,ko_kr}`에 있습니다. [Patchouli 리소스 책 형식](https://vazkiimods.github.io/Patchouli/docs/reference/book-json/)을 사용하며, 본문은 언어별 파일로 번역합니다. `i18n`은 꺼서 백분율 같은 일반 본문을 번역 형식 문자열로 해석하지 않도록 합니다. 책 이름·표지 안내·부제의 번역 키는 기본 언어 파일에서 관리합니다. 책의 `version`은 `0`으로 두어 판 번호 대신 번역한 부제를 표시합니다.

책 1개와 슬라임볼 1개의 조합법과 조합법 해금 발전 과제는 동일한 `forge:mod_loaded` 조건을 사용합니다. 동료의 동적 조합법은 원본 재료와 데이터를 유지하며, 책에서는 공통 아이템 도식으로 표시합니다. 일반 조합은 실제 조합법 페이지를 사용합니다.

`verifyGuidebook`은 한·영 경로와 페이지 구조, 분류·템플릿·내부 링크, 조합법 참조와 선택 의존성 조건을 검사하며 `check`와 `build`에 포함됩니다.

실제 책 검사에는 일반 개발 클라이언트에서 `slimic-smoke`라는 테스트 월드를 만들고 저장·종료한 뒤, `run/saves/slimic-smoke`를 `build/guidebook-client/saves/slimic-smoke`로 복사합니다. `./gradlew runClient -PclientSmoke=true -PguidebookSmoke=true`로 실행합니다. 별도 월드에서 서바이벌 2×2 제작·재료 소비·해금·크리에이티브 표시·언어 및 리소스 다시 불러오기·모든 페이지·글자 높이·아이템 연결·본문 링크·언어별 검색을 확인합니다. 검사는 복사본의 플레이어 인벤토리와 게임 모드를 변경합니다.

## 전투와 청소

`CombatSlime`은 검·방패·갑옷을 기본 장비 칸에 저장하고 일반 적재량 가방을 공유합니다. 동기화된 대상 마스크는 독립된 6개 비트를 사용하며, 메뉴의 소유권 검증으로 변경을 보호합니다. 필터나 명령이 바뀌면 현재 대상을 다시 검증합니다. 기본 근접 전투·갑옷·방패 준비 시간·마법 부여·내구도와 Forge 이벤트를 사용하며 설정과 재사용 대기 시간은 회수 후에도 유지합니다.

기본 갑옷 재질마다 별도 아이템을 등록하여 기본 수리와 네더라이트 내화성을 유지합니다. `SlimeArmorItem`은 `SlimeArmorBase`에 원본 흉갑을 저장합니다. 변환 후에는 바깥 아이템의 손상·마법 부여·표시·속성 데이터를 기준으로 삼으며, 재질별 속성과 내구도는 원본 흉갑에 위임합니다. 조합은 등록된 흉갑과 검을 지원하고 JEI 미리보기도 동적으로 구성합니다.

`CleaningSlime`은 공통 기본값과 조작기 값을 유지하면서 실제 탐지 범위만 5배로 적용합니다. 고정 배치 지점 주변에 로드된 엔티티만 수거 대상으로 탐색합니다. 서버 스레드에서 가방 공간을 시뮬레이션하고 부분 묶음을 보존하며 습득 대기 시간·소유권·이벤트를 따릅니다. 3,600틱 시도 후 다른 대상을 찾거나 재시도하고 아이템 보관 중에는 저장된 시간이 멈춥니다. 작업 명령은 대기 중에도 이동을 점유하여 임의 배회를 막습니다. 운반은 공통 가방 포화·교체 도구 인터페이스를 이용합니다.

검증은 대상 기본값·전환·소유권, 기본 전투·방어, 재질과 NBT 변환, 화물·재시도 상태 보존, 수거 범위와 대기, 실제 습득·복귀, 가방 포화, 검 보급, 선택적 JEI와 번역된 조작 화면을 포함합니다. 전투 테스트는 평화로움 난이도 테스트 배치 이후에 실행합니다.

## 시각 에셋 규칙

소환 아이템은 `slime_summon_base` 모델과 친근한 슬라임 텍스처를 공유합니다. 하위 모델에서 직업 문장을 선택하여 특화 아이템의 작은 틀에 배치합니다. 친근한 슬라임은 문장 요소를 재정의해 금블록 텍스처 전체가 보이는 평평한 표식을 표시하고, 눅눅 슬라임은 등록된 슬라임 슬래그 텍스처를 사용합니다. 그 밖의 새 아이템에는 제한된 색상과 명확한 윤곽을 가진 마인크래프트 스타일의 전용 16×16 도트 텍스처를 함께 추가합니다. 도트 이미지를 준비할 때는 최근접 이웃 방식으로 크기를 조정합니다. 슬라임 갑옷 6종은 `slime_armor_base` 모델을 상속하여 같은 회색조 윤곽과 염색되지 않는 슬라임 표식을 공유합니다. 아이템 색상 처리로 재질을 구분하고 원본 가죽 염색을 유지합니다. 블록 아이템은 텍스처가 적용된 블록 모델을 상속하여 인벤토리와 설치 외형을 일치시킵니다. 동료의 장식은 별도 텍스처를 사용하고 슬라임 염색 시에도 색을 유지합니다.


직업 장식은 전용 `textures/entity/accessories/*.png` 아틀라스를, 관리·조작기·명부·슬롯 배경은 `textures/gui/*.png`를 사용합니다. 형태와 애니메이션은 클라이언트 모델에서 정의합니다. 파일별 용도·UV 좌표·리소스 팩 교체·실제 외형 검증은 [텍스처 편집](TEXTURES.kr.md)에 정리되어 있습니다.


`FriendlySlimeItem`은 모든 특화에 실제 아이템의 `<description_id>.tooltip` 키를 사용해 직업 설명 하나를 표시합니다. 공통 안내는 새 소환과 저장 개체 복원을 구분합니다. 하위 클래스는 최초 곡괭이처럼 아이템별 상태만 추가하고 직업 설명을 중복하지 않습니다. 영어와 한국어에 스물두 직업의 설명을 제공합니다. 실제 클라이언트의 `slimic.companionTooltipsOnly` 검증은 새·저장 아이템, 일반·고급 툴팁, 두 글꼴, 대체 언어, 기본 화면 경계, 저장 데이터 보존을 확인합니다. JEI 정보는 시작 시 등록된 언어를 기준으로 검사합니다.

## 작업 상태 복원

`WorkDimension`은 동료의 작업 상태에 해당하는 차원을 기록합니다. Forge 텔레포터 이동이 성공하면 도착 지점에서 재배치 훅을 실행합니다. 첫 서버 틱에서도 AI 실행 전에 저장된 차원을 확인하여 기본 차원 이동으로 복원된 엔티티 사본을 처리합니다. 채굴은 청크 좌표와 차원 식별자를 함께 사용합니다. 운반과 청소는 명령과 화물을 유지하면서 고정 작업 중심을 갱신합니다. 같은 차원의 저장 데이터는 기존 구역을 유지하며, 이 필드가 없는 이전 저장 데이터는 불러온 차원을 채택합니다. `onReleased`를 재정의하는 특화는 기본 구현을 호출하여 기록된 차원도 새 작업 구역과 함께 갱신해야 합니다.

`TransportCooldown`은 작업 속도에 따른 남은 동작 대기 시간을 지원 범위인 0~200틱 안에서 보존합니다. 경로와 작업 대상은 불러온 뒤 다시 선택합니다. 운반 경로는 지면에 있을 때만 교체하고, 수평 이동 또는 착지한 높이의 진척이 없는 시간을 측정하므로 제자리 점프만으로 정체를 숨기지 않습니다.

전투 추적과 청소 복귀도 수평 이동이나 착지 높이의 진척이 없는 400틱을 측정하며 제자리 점프는 제외합니다. 다시 전진하면 막힘 상태를 해제합니다. 점프 중에는 유효한 경로를 유지하고, 전투 대상이 이동하면 목적지를 갱신하며, 새 복귀마다 자체 정체 타이머를 초기화합니다. 느린 이동, 실제 정지, 도착 전 이동 재개와 정확한 청소 복귀를 회귀 검사합니다.

회귀 검사는 같은 좌표의 다른 차원으로 채굴 복원, 포털·명령 방식의 복원, 이동 취소, 이전 저장 데이터, 같은 차원의 작업 중심, 느리지만 전진하는 배달, 정지한 운반 슬라임, 회수 후 동작 대기 시간 보존을 포함합니다.

청크 단위 작업 검사는 독립적으로 로드한 전체 청크의 자연 지형을 정리한 구역을 사용합니다. 이를 통해 채굴 대상과 화물 전달 검사가 작은 구조물 템플릿의 배치나 인접 지형에 좌우되지 않도록 합니다.

## 공통 작업 규격과 데이터 호환성

`WorkStatus`는 지정된 `Order`, 실행 `State`, 중단 `Reason`, 지원 `Request` 집합을 분리합니다. 기존 직업별 상태는 표시·저장 형식으로 유지하며 각 직업이 공통 규격으로 변환합니다. 따라오기·대기는 지원 요청을 억제합니다. 작업 명령이 활성화된 동안에는 주인이 로드되지 않아도 기본 앉기 목표가 이동을 점유하지 못합니다. 물류는 화물·도구 요청을 사용하고, 파발은 직업별 열거형 대신 `BLOCKED`를 사용합니다. 전달 직전에 장비와 소유권을 다시 검사합니다.

`WorkSearch`는 로드된 청크의 불변 후보 목록을 운반 슬라임끼리 20틱 동안 공유합니다. 후보 목록만 캐시하고 요청·범위·소유권·잠금·적재 공간은 매번 검사합니다. 갱신 시 오래된 구역을 제거하고 월드 해제 시 캐시를 비웁니다. 없는 청크는 티켓을 추가하지 않고 빈 목록을 반환합니다. 유휴 운반 탐색은 개체별로 시점을 분산합니다. 이동 중 탐지 범위가 줄어든 경우에도 적재·도구 수거 직전에 선택한 상자가 현재 작업 반경 안에 있는지 다시 확인합니다. 100회 반복 조회와 32마리 동시 운반 검사는 정확성·부하 시나리오이며 하드웨어 TPS 벤치마크는 아닙니다.

기력은 기존 회복 기회에 최대치의 2%씩 회복합니다. 전달 활동 보상은 설정 가능하며 기본 4입니다. 실제 소유자 따라오기 이동과 활동 중인 동료의 감시도 기본 100유효틱마다 성장합니다. 부분 타이머는 저장하며 아이템 보관 중에는 진행하지 않습니다. 실패·유휴·대기만으로는 성장하지 않습니다. 모든 동료는 처음 소환할 때 대기하며 저장된 명령이 없을 때도 대기를 선택합니다. 모든 아이템 재배치와 부활은 저장 데이터·장비 복원과 구역 갱신 이후 대기를 적용합니다. 일반 월드 로드는 저장된 명령을 유지합니다.

`SlimeDataVersion`은 현재 월드·회수 아이템의 슬라임 데이터에서 1입니다. 마이그레이션 진입점은 버전 없음·0인 데이터를 기존 필드 삭제 없이 받아들입니다. 지원하지 않는 미래 버전이나 잘못된 형식의 저장 아이템은 변경 없이 소환을 거부합니다. 직업별 기존 NBT 키와 누적 포인트는 유지합니다. 저장 필드 의미나 구조를 변경하기 전에 명시적인 마이그레이션 단계를 추가합니다.

## 알림 기록과 메뉴 동기화 안정성

파발 경고 기록은 큰 집단에서도 잘리지 않으며 작업자 UUID마다 마지막으로 신호를 보낸 작업 불능 회차를 유지합니다. 월드와 회수 아이템에 같은 기록을 보존하며, 불러올 때 잘못된 UUID나 회차 값은 무시합니다. 새로운 경고가 다른 작업자의 기록을 삭제하지 않습니다.

플레이어 대상 탐색과 실제 근접 공격 전에 서버 PVP 설정과 로드된 소유자의 플레이어 피해 권한을 확인합니다. 기본 팀·동맹 제외도 유지합니다. 검사 후 서버 PVP와 점수판 상태를 복원합니다.

기본 컨테이너 데이터 패킷은 부호 있는 16비트 값만 전달합니다. `IntContainerData`는 각 논리 정수를 두 부분으로 나누고 초기 스냅샷 완료 표식을 덧붙입니다. 관리창과 조작기는 이 전송을 공유하여 큰 실제 속성을 보존하고, 작은 값으로 돌아오면 이전 상위 비트를 지웁니다. 편집 화면은 완료 표식 이후 초기값을 읽습니다. 프로토콜 16은 이 구성과 탑승 조작을 포함합니다. 실제 기본 패킷 직렬화, 두 메뉴, 청소 탐지 범위의 큰 보정, 값 감소와 JEI 활성·비활성 클라이언트를 검증합니다.

## 안장 장비와 탑승

`SaddleSlime`은 기본 손에 안장, 보조 손에 겉날개, 흉부 칸에 슬라임 갑옷을 저장합니다. 장비 전용 메뉴는 플레이어 인벤토리 앞에 동료 슬롯 3개를 두며 기본 갑옷 속성·마법 부여·내구도는 날개와 별도로 적용합니다. `SaddleEquipmentVersion = 1`로 이 배치를 구분합니다. 이전 데이터의 흉부 겉날개는 원본 데이터를 유지해 보조 손으로 옮기고, 비표준 기존 보조 손 아이템은 회수할 수 있도록 흉부 칸에 보존합니다. 저장한 배치 표시로 재이동을 방지하며 공통 동료 스키마는 1을 유지합니다. 조합은 친근한 슬라임의 저장 특성과 정확한 재료 안장을 복사하며, 회수 아이템은 초기 장비를 다시 적용하지 않는 전용 소환 아이템으로 만듭니다.

일반 비행의 틱당 속도는 `min(0.45, 0.24 × sqrt(이동 속도 / 0.3))`이며 고속 비행은 1.75배를 적용합니다. 이동 속도가 유한하지 않거나 0 이하이면 추진하지 않습니다. 겉날개 없는 지상 고속 이동은 기존 2배를 유지합니다. 클라이언트 이동과 서버 차량 예측은 같은 계산을 사용하며 합성 입력 정규화와 기존 기력·하강 규칙을 적용합니다.

원래 주인과 공동 소유자만 한 자리의 좌석을 차지하고 조종할 수 있습니다. 우선 이동 목표가 탑승 중 동료 AI를 멈춥니다. 기본 탑승 입력·속도 훅으로 지상 조종과 점프를 처리합니다. 겉날개 이동은 충돌을 적용하는 엔티티 이동과 탑승자의 시선을 사용하며, 합성 방향 정규화·호버링·이동 속도 배율을 적용합니다. 서바이벌 탑승에서도 기본 차량 이동 패킷을 사용합니다. 별도 패킷은 상승·점프와 가속 입력을 전달하고, 서버는 보낸 플레이어가 해당 개체에 실제로 탄 소유자인지 검증합니다. 입력은 갱신 없이 30틱이 지나면 만료되고 하차하면 초기화합니다.

겉날개 탑승은 이동과 기본 차량 검증에 일시적인 무중력을 제공합니다. 저장에서는 계산된 비행 플래그만 제거하고 명시적인 기본 중력 재정의는 유지하여 회수한 개체가 혼자 떠 있지 않게 합니다. 안장은 전용 모델·가죽 텍스처를 사용하고, 좌우 독립 날개 모델은 전용 불투명 깃털 텍스처를 사용하고 비행 중 날갯짓합니다.

프로토콜 16은 탑승 메시지에 상승과 가속 입력을 전달합니다. 제작과 실제 소환, 소유권, 장비 Shift 이동, 탑승 회수, 사용할 수 없는 날개, 명시적·일시적 중력 및 JEI 유무별 실제 서바이벌 클라이언트의 조종·점프·상승·호버링·가속·시선·서버 차량 동기화·Shift 하차를 검증합니다.

## 성장 요구량과 채굴 일관성

공통 포인트 요구량은 32에서 시작해 획득한 포인트마다 64씩 증가하며 4,096에서 제한됩니다. 활동 진행도를 불러올 때 지원하는 나머지 범위를 유지한 뒤 새 요구량에 도달한 포인트를 먼저 지급하고 나머지를 보존합니다. 줄어든 요구량에 맞춰 기존 진행도를 잘라내지 않습니다. 실시간 작업 보상도 같은 정산을 사용합니다. 기존 포인트·능력치 투자·성장 단계·동료 특성을 유지하고, 정산된 데이터를 다시 불러와도 포인트를 중복 지급하지 않습니다.

명시적인 채굴 명령은 현재 청크와 기존 작업 청크가 다르면 작업 계획을 새 위치로 옮깁니다. 같은 청크에서는 저장된 계획을 유지합니다. 이동 진척은 수평 0.05블록 또는 착지 높이 0.5블록으로 판단하여 400틱 안에 반 블록을 이동하지 못하는 저속 접근도 계속 전진할 수 있습니다. 현재 블록 상태를 추적하고 교체되면 누적 채굴 진행도와 파괴 표식을 초기화합니다.

운반 가방은 슬라임 외곽 몸체 뒤에 배치하고 옆·뒤 끈도 몸체 표면에서 분리합니다. 내부 몸체와 가방의 동일 평면 및 외곽 표면 겹침을 제거하면서 자세·눌림 변환은 함께 적용합니다. 크리에이티브 탭은 동료 아이템을 모은 뒤 보관함·재질 순 갑옷·조작기와 탐색기를 표시합니다.

회귀 검사는 스물두 종류 동료의 초기 성장 요구량, 기존 진행도 200의 보존·중복 지급 방지, 따라오기 후 다른 청크에서 채굴 시작, 저속 전진, 블록 교체 후 정확한 드롭과 도구 소모를 포함합니다. 클라이언트에서는 가방을 여러 각도에서 확인하고 실제 크리에이티브 아이템 순서를 기록합니다.

## 위협, 쓰러짐과 활동 성장

엔티티 진입 훅은 크리퍼와 엔더맨을 제외한 적대적 `Enemy` 몹에 동료 대상 목표를 추가합니다. 정확히 바닐라 `EntityType.SLIME`인 경우에만 `getLastHurtByMob()`에 기록된 동료를 대상으로 선택합니다. 마그마 큐브와 다른 등록 슬라임 종류는 기존 대상 선택을 유지합니다. 전투 대상 분류와 필터는 바꾸지 않으므로 적대 설정이 켜진 전투·드래곤 슬라임은 먼저 공격할 수 있습니다. 피해와 투사체 처리는 기존 공격 AI를 사용합니다. 우선순위가 높은 도주 목표는 전투 슬라임을 제외한 동료가 실제 공격자에게 대응하도록 하며 탑승 조작에 양보합니다. 점프 추진력은 공통 기본값을 유지하고 이동 속도 속성은 지상 대기 시간을 정합니다. 지상 탑승 이동도 같은 원칙을 사용합니다.

취소되지 않은 `LivingDeathEvent`를 가장 낮은 우선순위에서 처리해 기본 장비·화물·경험치 드롭 전에 동료를 보존합니다. `BrokenSlimeBlockEntity`는 특화된 회수 스택을 `Slime`에 저장합니다. 사망 위치가 교체 가능하면 블록을 설치하고, 점유되어 있으면 지형을 덮어쓰지 않고 블록 아이템을 남깁니다. 기본 블록 전리품은 이 데이터를 `BlockEntityTag.Slime`으로 복사하여 채굴·재설치 후에도 유지합니다. 부활은 기존 소환 및 UUID 검증을 거쳐 현재 생명력을 1로 설정하고 사망·화염·운동 상태를 지웁니다. 성공할 때만 블록과 슬라임볼을 소비하며 소환 실패 시 블록 엔티티를 복구합니다.

동맹이 아닌 공격자의 실제 피해와 방패 방어는 20틱에 최대 1회 진행도를 지급합니다. 소유자와 환경 피해에는 보상이 없습니다. 도주·탑승 이동은 따라오기 성장 설정 주기를 사용합니다. 방패를 든 전투 슬라임은 몸체 방향을 대상으로 돌리고 공격 간격을 최소 10틱으로 유지하여 기본 방어 준비 시간을 확보합니다.

파발 슬라임은 사건 기록과 별도로 `HeraldWarningCooldowns`에 작업자별 반복 대기 시간을 저장합니다. 첫 신호 이후 200틱의 감시 시간마다 반복하며 보관 중에는 멈추고 막힘이 해소되거나 범위를 벗어난 동료에는 발사하지 않습니다. 기존 `HeraldCooldown`은 저장된 경고 기록별 대기 시간으로 불러옵니다.

프로토콜 16은 탑승 입력을 상승과 가속으로 변경합니다. 가속 상태는 동기화하고 서버에서 공중 비행은 틱당 기력 0.1, 지상 고속 이동은 0.5, 고속 비행은 0.75를 사용합니다. 고갈되면 상승을 막고 틱당 0.12블록의 완만한 하강 상태를 동기화합니다. 공중에서는 회복하지 않으며 착지 후 25%까지 회복해야 비행·고속 이동을 재개합니다. 장비와 저장 동료의 데이터 구조는 호환되며 `SlimeDataVersion`은 1을 유지합니다.

## 지상 작업자

`FieldSlime`은 기본 주 손 도구 하나, 일반 가방, 기력 회복, 로드 영역 검사, 보호된 수확·배치와 FARM/LOG 명령을 공유합니다. 가방 포화는 CARGO_PICKUP, 파손으로 빈 도구 칸은 TOOL_SUPPLY를 요청합니다. 씨앗 부족은 SEEDS_MISSING이며 도구 요청을 만들지 않습니다. 지형 변경이 성공한 작업만 활동 진행도를 얻습니다. 네트워크 프로토콜은 16입니다.

`BlockSurvey`는 일치하는 로드 청크 섹션의 팔레트를 복사하고 작업자 틱마다 최대 512칸을 검사합니다. 농사 활성화 당시의 경작지만 고정하며, 직렬화 시 남은 스냅샷을 마무리해 회수 중 등록 농지가 유실되지 않습니다. 농지 좌표와 작물 종류를 저장합니다. 경작은 장착 괭이의 Forge 도구 동작과 배치 취소 이벤트를 사용합니다. 수확은 소유자 명의 생존 모드 파괴 이벤트를 거치고 지형을 바꾸기 전에 전체 드롭의 수납을 검사합니다.

벌목 탐색은 틱마다 연결 후보를 최대 64개 검사하며 나무 계획을 수확 블록 512개·방문 칸 4,096개로 제한하고 청크를 로드하지 않습니다. 밑동 토양과 자연 잎을 확인해 장식 구조물을 제외합니다. 벌목 전에 해당 묘목을 확보하고 운반 가능한 화물과 별도로 저장합니다. 원목 대기열과 재식재는 월드 다시 불러오기 후 이어지며 다시 소환하면 새 중심을 정하고 미사용 묘목을 반환합니다. 두 직업은 조작기 기본값을 유지하면서 실제 탐지 범위에 2배를 적용합니다.

맹그로브 탐색은 중앙 뿌리와 공기·물로 된 틈을 따라 유효한 재식재 토양까지 확인하고, 계획된 중앙 뿌리 블록만 수확 대기열에 포함합니다. 선택 저장 필드 `LoggingRootColumns`는 원목과 뿌리 좌표를 구분하므로 플레이어가 대기 원목을 뿌리로 교체해도 그 블록을 수확하지 않습니다. 불러올 때 저장 대기열에 속한 항목을 최대 512개만 인정하며 필드가 없으면 빈 집합으로 처리해 스키마 1 호환성을 유지합니다. 주아는 기본 심기 상태의 나이로 배치하고 기존 물 근원에만 물이 찬 상태를 적용합니다.

`SlimeTunerItem`은 슬라임볼과 철 주괴로 조합하는 서바이벌 관리 도구입니다. 크리에이티브 편집은 `CreativeSlimeTunerItem`, `CreativeSlimeTunerMenu`, `CreativeSlimeTunerScreen`, `creative_slime_tuner`, `creative_tuner`로 구분합니다. 프로토콜 16은 변경된 편집 패킷, 가디언 엔젤 메뉴 배치와 파발 수동 발사를 반영합니다. 관리 명령은 서버에서 소유권·생존·차원·거리·일반 조작기 소지를 검증합니다. 치료와 세척은 실제 변경이 있을 때만 소비하며 회수가 우선합니다.

`GuardianAngelSlimeRecipe`는 원본 동료 상태와 토템을 보존하며 초기 토템은 `InitialGuardianTotem`에 저장합니다. 가디언 엔젤 슬라임은 `GuardianTotems`와 공격 대기 시간을 저장합니다. 고정 UUID의 영구 최대 생명력 보정으로 다시 불러오기 시 중복 없이 10배를 유지하며 기본 게임의 한계에 맞춰 크리에이티브 기본 생명력을 102.4로 제한합니다. 비행 내비게이션과 이동 제어는 공통 이동 속도를 반영하는 전용 비행 속도 속성을 사용합니다. 반격 대상과 광선은 일시 상태입니다. 최저 우선순위 피해 이벤트가 주인의 공격자를 전달하며 시야·동맹·범위·자원을 검사합니다. 취소되지 않은 사망 이벤트에서 가까운 소유 가디언 엔젤 한 마리만 토템 사용 이벤트를 거쳐 보호합니다. 주인이 든 일반 토템은 사망 이벤트 전에 처리됩니다. 광선은 기본 번개 렌더 타입에서 양면을 표시합니다.

토템 칸은 데이터가 같은 토템을 64개까지 허용합니다. 일반 회수는 한 개씩이며 Shift+클릭은 인벤토리의 한 개 제한을 지켜 분배하고 초과분을 남깁니다. 컨테이너 변경은 동기화 상태를 갱신합니다. 기본 메뉴 클릭·이전·저장·주인 피해·비행 반격·치명상 보호는 GameTest와 클라이언트 검증 범위에 포함됩니다.

지상 작업자는 원목이나 작물 내부 대신 작업 거리 내 충돌 없는 발판을 찾습니다. 발판 후보와 경로 끝점의 높이는 기본 `WalkNodeEvaluator.getFloorLevel`로 계산하여 진흙처럼 충돌 높이가 낮은 지형도 반영합니다. 벌목은 잠시 작업할 수 없는 밑동을 캐싱하고 필요한 묘목 종류·밑동 수를 동기화하며 다른 수종을 계속 탐색합니다. 가방 변경 시 조사 캐시를 갱신합니다. 농사와 벌목은 별도 번역 키를 사용합니다. 채굴은 목재·도끼·괭이 대상을 제외하고 경로 끝점을 재검증하며 기본 계단 접근을 유지합니다. 이동 진전은 목표까지 가까워진 거리로 판정하여 제자리 점프가 재시도를 무기한 미루지 않게 합니다. 도주 내비게이션은 공중 점프 중 경로를 유지하고 착지 후 공격자에게서 멀어지는 끝점의 경로로만 교체합니다.

슬라임 상자는 기존 보관·자동화·드롭 기능을 유지합니다. 기본 개방 인원 카운터가 소리와 블록 이벤트를 전달하고 클라이언트 뚜껑 제어기가 각도를 보간합니다. 렌더러는 바닐라 단일 상자의 본체·뚜껑·걸쇠 비율과 64×64 UV 배치를 사용하며 뒤쪽 경첩을 기준으로 회전합니다. 걸쇠는 뚜껑과 함께 움직이고, 아이템도 같은 아틀라스와 형태의 닫힌 3D 블록 모델을 사용합니다.

## 경계 조건 회귀 검사

관리 화면은 명령과 인벤토리 조작마다 관전자 상태를 재검사합니다. 화면을 연 뒤 게임 모드를 변경해도 적용됩니다. 슬라임볼 치료는 Forge 회복 이벤트 전후의 생명력을 비교하며, 취소되거나 회복량이 0이면 아이템 소비와 회복 효과를 발생시키지 않습니다.

벌목 슬라임은 도달할 수 없거나 습득이 금지된 드롭 아이템을 200틱 동안 보류하고 다른 작업을 이어갑니다. 묘목 요구 표시는 해당 밑동이나 자연 잎이 사라지거나 가방·작업 원점이 바뀌면 지웁니다. 일시적인 탐색 캐시는 데이터를 불러온 뒤 다시 구성합니다. 가디언 엔젤의 가시성 검사는 몸체와 광선의 경계 상자를 함께 반영합니다.

## 유체 작업·흔적·계단 이동

채굴은 현재 굴착 층의 물·용암을 일반 블록보다 먼저 탐색합니다. `BUCKET_MISSING` 원인과 `BUCKET_SUPPLY` 요청으로 양동이 부족을 구분합니다. 채굴 슬라임의 사용 가능한 가방 칸에 있는 빈 양동이만 제거를 허용하며, 가방이 가득 차면 화물 수거도 요청합니다. 운반은 요청·수용량·허용 아이템을 다시 검증하고 원본 양동이 한 개만 전달합니다. 유체 제거는 양동이를 소비하거나 채우지 않습니다. Forge 파괴·설치 권한을 확인하고 취소된 변경은 복원하며, 물에 잠긴 블록 엔티티는 보존합니다. 성공 후에만 기력·성장을 적용하고 저장되는 유체 대기 시간으로 처리 빈도를 제한합니다.

유체 탐색은 도달할 수 있는 노출된 수원을 우선하며 한 번에 가로 최대 3×3칸을 제거합니다. 수원을 처리하는 묶음에서는 흐르는 물을 반복 제거하지 않고 남은 수원을 먼저 없앱니다. 각 칸의 도달 거리·시야·Forge 권한·양동이·기력을 별도로 확인합니다. `MiningDrainedWaterLayer`에 현재 물 제거 층을 저장하며, Forge 유체 수원 이벤트에서 이 작업 층의 물이 수원 재생에 기여하지 못하도록 합니다. 활성 물 제거 상태를 로드된 월드와 청크별로 등록하여 주변 개체 탐색이나 청크 로드 없이 확인하고 작업 중단·층 변경·개체 제거 시 제한을 해제합니다. 전역 게임 규칙은 바꾸지 않습니다.

`SoggySlime`은 공통 동료 상태와 저장되는 흔적·회복 타이머를 사용합니다. 서버 설치는 빈 공간·로드된 단단한 지지면·권한을 요구합니다. 취소 시 스냅샷을 복원하고 기력이나 성장을 적용하지 않습니다. `SlimeTrailBlock`은 카펫 형태와 삽 태그, 슬래그 한 개 드롭을 사용합니다. 재활용 조합은 슬래그 네 개를 소비합니다. 소환 모델은 공통 바탕과 고유 문장을 사용하며 슬래그는 투명 배경의 전용 16픽셀 텍스처를 갖습니다.

지상 점프 제어는 이동 요청뿐 아니라 기본 `JUMPING` 상태에서도 추진력을 제한합니다. 이동 속도 속성은 점프 간격에 적용하며 계단을 오르는 중 과도한 추진력이 다시 적용되지 않습니다. 가디언의 자기 방어는 주인·동맹을 제외하고 대기나 주인 접속 종료 중에도 작동합니다. 토템 보호는 공통 치명상 이벤트를 사용해 환경 피해도 처리하며 기본 우회 피해 예외를 따릅니다.

회귀 검증은 모든 지상 직업의 점프 상태, 실제 낙하·용암·익사·화재 치명상, 주인 부재 시 자기 방어, 흔적 비용·드롭·설치 취소, 눅눅 슬라임 저장, 유체 변경 취소 복원, 양동이 데이터 보존, 물에 잠긴 보관함, 운반의 하역 후 양동이 보급을 포함합니다. 실제 클라이언트에서는 새 모델·흔적 렌더링·관리 화면·선택적 JEI 조합을 확인합니다.

공통 FriendlySlime 생성자는 하위 클래스의 명령 설정 메서드를 호출하지 않고 모든 동료를 대기로 초기화합니다. 새 소환 아이템은 장비 초기화 후에도 대기를 적용합니다. 엔티티 데이터에 Sitting이 없거나 직업 명령 데이터가 없을 때, 처음 특화할 때도 대기를 선택합니다. 일반 월드 로드에서는 저장된 명령을 유지하고, 아이템 재배치와 부활에서는 대기로 전환합니다. 스물두 종류 모두 생성·명령 없는 엔티티 NBT·월드 데이터 저장과 복원·실제 아이템 소환·회수 시 개체 식별자와 자원을 보존한 대기 전환을 검증합니다. 안장 조합은 저장된 따라오기를 대기로 전환하면서 개체 식별자·자원·원본 안장을 유지하는지 확인합니다. 작업 검증은 시작 명령을 명시합니다.

가디언은 흡수 생명력으로 받은 실제 피해에도 반격하며, 길들이지 않은 개체는 소유권에 의존하는 대상 검사를 안전하게 거부합니다. 두 조건은 네이티브 회귀 검사로 확인합니다.

물에 들어온 슬라임은 새 이동 목표를 받을 때 이전 지상 점프 상태를 해제합니다. 물살을 거슬러 이동할 수 있도록 수영 입력을 유지하며, 채굴 경로는 수면과 물속 경유 지점의 높이 차이를 허용합니다.

## 화면 문구와 용어

게임 화면과 게임플레이 가이드는 생명력·공격력·방어력·이동 속도·작업 속도·적재량·지구력·도달 거리·탐지 범위라는 능력치 이름을 공유합니다. 지구력은 최대 기력을 나타내며 현재 소비·회복하는 자원은 기력으로 구분합니다. 성장 수치는 활동 진행도, 강화에 사용하는 수치는 능력치 포인트로 표시합니다.

따라오기·대기는 주인이 선택한 명령이며, 자원 부족 등으로 작업을 진행하지 못하는 상태는 작업 중단으로 설명합니다. 농사와 벌목 상태는 각각의 작업 대상을 명시합니다. 상태 안내는 간결한 설명문, 필요한 조치는 정중한 요청문으로 작성합니다. 버튼은 짧은 동작 이름을 사용합니다. 기본 게임의 아이템 이름은 해당 언어의 Minecraft 번역을 따릅니다.

번역 키와 저장 데이터 식별자는 문구 수정으로 바꾸지 않습니다. 한영 번역의 키·서식 지정자·문서 링크를 함께 확인하고 실제 화면에서 줄바꿈, 버튼 너비와 도움말 영역을 검사합니다.

## 채굴 벽과 자유 이동

`QuarryWalls`는 작업 청크의 네 외측 면에서 최대 192칸을 확인하며, 층 변경을 제외하면 20틱에 한 번만 조사합니다. 로드된 측면 유체와 지하 2×2 공기 구멍을 지속 작업 목록에 등록하고, 안쪽 채굴면이 드러난 칸부터 처리합니다. 외측 한 겹을 보강하여 계단 두 줄을 보존합니다. 미완료 칸은 현재 계획의 범위로 검증·제한하여 `MiningWallPending`에 저장하며, 작업 청크나 차원이 바뀌면 새 목록을 만듭니다. 조사와 경로 탐색은 이웃 청크 티켓을 추가하지 않습니다.

`COBBLESTONE_MISSING` 원인과 `COBBLESTONE_SUPPLY` 요청으로 채굴을 멈추며, 가방 공간이 없으면 `CARGO_PICKUP`도 요청합니다. `BagSlime.workSupplyLimit`와 `receiveWorkSupply`의 기본값은 기존 도구·양동이용 1개입니다. 벽 재료를 요청한 채굴 슬라임은 최대 64개를 받으며, 전달 직전에 요청·소유권·공간을 다시 확인합니다. 운반은 실제 수용한 수량만 꺼냅니다. 조약돌 설치 성공 후에만 재료·기력 1을 소비하고 활동 진행도 1을 더합니다. Forge 설치 취소 시 스냅샷을 복원하고 비용을 적용하지 않으며, 교체 불가 블록과 점유된 칸은 보존합니다.

`SoggyRoaming`과 `SoggyRoamHome`은 선택적인 ROAM 명령과 구역 중심을 저장하며 스키마 버전 1을 유지합니다. 필드가 없는 저장 데이터는 기존 따라오기·대기를 유지합니다. 자유 이동은 MOVE/LOOK을 점유하고 범위 안의 지지면이 있는 임의 목적지를 고르며, 경로 영역의 모든 청크가 이미 로드된 경우에만 탐색합니다. 주인의 접속 여부에 의존하지 않고 도주에 양보합니다. 따라오기·대기는 자유 이동을 해제하고 재소환은 구역 중심을 갱신합니다. 지형이 바뀌면 경로를 해제하고 구역 안에서 다시 선택하여 이전 따라오기 목적지가 재사용되지 않게 합니다. ROAM 중에도 흔적 생성에 필요한 기력을 회복할 수 있도록 회복 조건을 재정의합니다. 메뉴는 기존 모드 필드로 ROAM을 동기화하며, 프로토콜 16은 같은 버전의 클라이언트를 요구합니다.

실제 서버 회귀 검사는 유입구 교체, 회수 후 개구부 보강, 정확한 설치 비용, 설치 보호, 재료 부족, 한 묶음 제한·부분 재고 보급, 메뉴 권한, 주인 없는 실제 자유 이동과 흔적, 명령 전환, 특성 저장, 기력 고갈 후 회복을 포함합니다.

## 엔더맨 대상 선택

엔더맨에는 동료 대상 목표 AI를 추가하지 않습니다. 전투 분류는 일반 NeutralMob 규칙보다 먼저 현재 목표를 확인합니다. 살아 있는 FriendlySlime을 노리는 엔더맨은 HOSTILE, 그 외에는 NEUTRAL을 적용합니다. 대상 선택과 공격은 현재 분류와 기존 필터를 다시 검사합니다. 실제 서버 검사는 목표 집합 보존, 중립·적대 전환, 무관한 목표, 실제 전투 후 적대 해제를 포함합니다.

## 도구 적합성과 블록 파괴 시간

`SlimeBlockBreaking`은 채굴과 `FieldSlime.harvest`에서 기본 `getDestroyProgress` 파괴 시간을 공유합니다. 기본 효율 마법 부여와 같은 조건으로, 장착 도구의 기본 파괴 속도가 1보다 클 때만 작업 속도 배율을 적용합니다. 대상에 맞지 않는 대체 도구는 기본 파괴 속도를 유지합니다. 도구가 없거나 내구도가 소진됐거나 필수 등급이 부족하면 파괴 진행도를 쌓지 않습니다. 기본 경도가 0인 작물은 직업에 필요한 괭이를 장착했을 때 기존처럼 즉시 수확합니다. 벌목은 기존 동작 대기 시간에 더해 실제 도끼의 기본 파괴 시간을 계산합니다.

일시적인 파괴 상태는 블록 위치·상태와 마법 부여·손상도를 포함한 도구 사본을 식별합니다. 이 값이 바뀌거나 작업이 중단되고 명령·구역이 바뀌거나 개체가 제거되면 진행도와 파괴 표식을 지웁니다. 저장·회수 후에는 부분 파괴를 처음부터 시작하며, 저장된 작업 구역과 완료 활동은 유지합니다. 보호 검사를 통과해 블록을 제거한 뒤에만 내구도·기력·화물·성장을 적용합니다.

실제 서버 회귀 검사는 최대 작업 속도에서 도구 부재·부적합·등급 변경·마법 부여 변경에 따른 파괴 시도 틱을 계측합니다. 나무·다이아몬드 도끼의 시간 차이, 적합한 도구의 속도 보너스, 농사·벌목의 전용 도구 요구와 재개를 확인합니다. 터널 굴착도 같은 파괴 시간 추적기를 사용합니다. 유체 제거·벽 설치·경작·심기·플레이어의 부활 조작은 각각의 자원·권한 검사를 사용하는 별도 동작입니다.


## 치유와 이동식 보관소

`HealingSlime`은 가방·작업 명령·휴식 상태·재사용 간격·탐색 중심을 저장합니다. 분산된 주기로 로드된 엔티티와 청크의 블록 엔티티만 탐색합니다. 생명력 회복에는 Minecraft의 치료 이벤트 경로를 사용합니다. 망가진 슬라임은 플레이어 상호작용과 같은 트랜잭션 방식의 부활 함수를 사용하며, 블록을 제거하기 전에 소유자 권한과 Forge 블록 보호를 확인합니다. 성공한 뒤에만 비용과 활동량을 반영하고 실패한 대상은 잠시 재시도에서 제외합니다. 부활 생명력 1 규칙을 공통으로 유지합니다.

`WarehouseSlime`은 운반 동작을 상속하고 적재량 배율 8과 물리 가방 216칸을 사용합니다. 같은 `TransportBag` 데이터로 전직 시 화물을 보존하며, 조합법은 이전 직업 명령을 해제하여 대기로 시작합니다. `WorkStorage`는 로드된 같은 소유자 또는 상호 공동 소유 관계의 창고 엔티티와 접근 가능한 슬라임 상자를 조회하고 창고를 먼저 정렬합니다. UUID 또는 블록 위치로 지정한 목적지는 이전 직전에 다시 검증합니다. 가득 찬 보관소는 건너뛰고 접근할 수 없는 보관소는 잠시 제외합니다. 창고는 일반 운반의 상자 적재 단계를 생략하여 화물이 순환하지 않도록 하며, 따라오기나 대기 중에도 다른 운반 슬라임의 보관소로 사용할 수 있습니다. 기존 열거형 순서를 유지하면서 치유·보관 명령과 슬라임볼 보급 요청을 추가합니다. 저장 데이터 스키마는 1이며 네트워크 프로토콜은 **16**입니다.

## 로드된 경로와 지원 작업의 경계 조건

`WorkNavigation`은 작업 중인 동료에게 범위가 제한된 지상 경로를 제공합니다. 경로 영역은 `getChunkNow`로 청크를 읽고 사용할 수 없는 지형을 통과 불가능한 경계로 취급합니다. 영역 생성은 이미 로드된 시작 청크만 참조하며, 직사각형 전체의 청크를 불러오지 않고도 로드된 우회 경로를 탐색합니다. 탐색량은 최대 4,096개 노드로 제한합니다. 지상 동료의 추종 모드는 기본 경로 탐색을 사용합니다. 가디언 엔젤 슬라임의 비행은 같은 `LoadedPathRegion`을 공유하는 `LoadedFlyingNavigation`을 사용하며, 목적지·경로 셀·직선 비행 광선에서 아직 로드되지 않은 청크를 불러오지 않습니다.

치유 상태는 가방 포화와 재료 부족을 구분하고 보급을 받은 즉시 요청을 재검증합니다. 보급 API는 호출자가 건넨 스택을 변경하지 않으며 슬라임볼을 한 번에 최대 64개만 받습니다. 운반 슬라임은 보급처를 선택하기 전에 자신의 가방 여유 공간도 시뮬레이션합니다. 실패한 치료 대상이 여전히 유효하면 재시도 제외 기간에도 작업 중단 상태를 유지하며, 다른 동료가 치료를 완료하면 해당 장애 상태를 해제합니다. 플레이어 부활 상호작용은 실제 사용한 손의 아이템과 블록 면을 전달해 모험 모드의 사용 권한 조건을 보존합니다.

독립 회귀 검증은 청크 경계, 로드된 우회 경로, 기본 치료 이벤트 취소, 보호된 부활, 동시 운반과 정확한 아이템 데이터를 확인합니다. 벌목 검증 지형은 로드된 이웃 청크의 무관한 자연 나무를 제거해 생성된 숲이 별도의 작업 대상으로 선택되지 않도록 합니다. 장시간 동작은 고정된 탐색 완료 시각 대신 관측 가능한 상태 전환으로 검증합니다.

`HealingTreatmentBlocked`는 접근 재시도와 저장·불러오기 중에도 해결되지 않은 치료 중단을 유지합니다. 치료에 성공하거나 유효한 대상이 없을 때 해제하므로 경로를 다시 시도해도 파발 알림 시간이 누적됩니다.

저장 아이템을 복원하는 동기식 트랜잭션은 Forge 소환 콜백이 끝날 때까지 UUID를 예약합니다. 그 사이 다른 차원에서 같은 개체를 다시 복원하려 하면 아이템을 소비하지 않고 실패합니다. 취소와 예외를 포함해 `finally`에서 예약을 해제하며, 등록 이후에는 기존의 전체 차원 엔티티 검사로 중복 소환을 막습니다.

청크 캐시는 기본형 long 키를 사용하여 경로의 각 셀을 검사할 때마다 좌표 객체를 만들지 않습니다. 각 `SlimeStat`의 고정된 소문자 저장 키도 한 번만 초기화하여 반복적인 능력치 조회에서 문자열을 새로 만들지 않습니다.

각 작업 목표는 `tick` 시작 시 현재 명령에 따른 실행 조건을 다시 검증합니다. 기본 목표 선택기가 다음 적격성 갱신까지 실행 중인 목표를 유지할 수 있기 때문입니다. 취소된 목표는 자원이나 지형을 바꾸지 않고 중단합니다. 독립 기본 서버 검증은 운반·창고·치유의 실행 중인 목표를 명령 취소 직후 다시 틱하여 이 경계를 확인합니다.

`LoadedBlockView`는 경로 영역과 작업 시야 광선에 공통의 로드 전용 청크 조회를 제공합니다. 아직 로드되지 않은 청크를 불투명한 블록으로 취급하므로 도달 거리 검사보다 먼저 실행되는 시야 판정도 청크를 불러오지 않습니다. 각 조회는 독립된 뷰를 사용하여 새로 로드된 지형을 다음 검사에 반영합니다. 일반 지상 추종에는 기본 시야 판정을 적용합니다.

치료는 Forge 콜백을 호출하기 전에 대상을 보관합니다. 이벤트 처리기가 치유 슬라임의 명령을 변경하면 임시 대상이 동기적으로 해제될 수 있기 때문입니다. 이미 완료된 치료는 비용을 한 번 반영하고, 취소된 치료는 비용을 반영하지 않습니다. 부활은 블록 보호 콜백 이후 작업 명령과 치유 슬라임의 생존 상태를 다시 확인한 뒤 지형을 변경합니다.

보호·줍기 콜백 이후에도 현재 작업 명령·소유자·차원·생존 상태를 확인한 뒤 작업을 진행합니다. 중단된 유체 제거·벽 보강·경작·심기는 블록 스냅샷을 복구하고 재료를 소비하지 않습니다. 줍기 콜백이 작업 명령을 바꾸면 이동 경로도 즉시 중단합니다. 채굴과 청소 시야 광선 역시 로드 전용 뷰를 사용하며, 기본 도달 거리 안의 대각선 청크 모서리도 같은 검사를 거칩니다.

파발은 신호를 발사할 때마다 남은 탐색의 감시 명령을 다시 확인합니다. 눅눅 흔적 설치는 보호 콜백 이후 대기·소유권·생존 상태를 재검증하며, 따라오기와 자유 이동에서의 정상적인 흔적 생성은 유지합니다.

로드된 작업 검증 지형은 성공과 실패 모두에서 강제 로드 청크를 해제하도록 종료 리스너를 등록합니다. 실패한 검증의 먼 청크가 이후 검사 동안 계속 활성화되는 것을 방지합니다.

가디언 엔젤 슬라임의 보호는 기본 토템 사용 콜백 전에 정확한 보관 토템을 복사하고, 콜백 이후 현재 소유권·거리·보관 데이터를 다시 확인합니다. 개체 제거·소유권 이전·토템 교체가 발생하면 비용이나 플레이어 효과를 적용하기 전에 보호를 취소합니다. 개체별 진입 상태는 재귀 보호를 막으며 `finally`에서 해제합니다.

탑승 비행은 클라이언트 이동과 서버 속도 예측에 같은 계산을 사용합니다. 서버는 기본 차량 패킷 검증을 위해서만 예측 속도를 유지하며, 다음 물리 처리·하차·날개 해제 전에 지웁니다. 월드 저장과 회수 아이템에는 예측 속도를 저장하지 않습니다. 실제 패킷 회귀 검사는 청크 관리자에 등록된 서바이벌 `ServerPlayer`로 전용 서버의 속도 검사를 거치며, 불가능한 이동의 거부도 확인합니다.

채굴 슬라임이 언로드된 작업 청크 밖에서 계속 활성 상태인 경우, 작업 틱은 기본 경로 탐색이 이전 경로 노드를 읽기 전에 남아 있던 경로를 지웁니다. 굴착 계획과 보관품은 유지합니다. 실제 회귀 검사는 원래 청크를 언로드하여 재로딩되지 않음을 확인하고, 지형을 다시 로드한 뒤 새 경로를 생성합니다.

허용된 설치 이벤트가 작물 나이·경작지 수분·묘목의 즉시 성장 상태를 바꾸더라도 완료된 현장 작업으로 처리합니다. 이벤트 이후 비용을 한 번 반영하며, 취소 시 스냅샷 복원은 유지합니다. 채굴 벽 보강은 변경된 블록이 유체 없는 단단한 벽을 이룰 때만 완료합니다. 유효하지 않은 변경은 유입구를 복원하고 일반 접근 실패 재시도 간격을 적용합니다.

## 추가 동료 직업

`FishingSlime`·`AbundanceSlime`·`TunnelSlime`·`DragonSlime`·`MeowSlime`이 다섯 직업을 추가합니다. 새 소환 아이템은 공통 소환 모델과 직업 문장을 사용합니다. 엔티티 레이어는 멜빵 바지·리라와 월계관·마인카트 외장·박쥐 모양 날개·바닐라 고양이 머리를 표시합니다. 치유 십자가의 앞면을 겹치지 않게 나누어 깊이 충돌을 방지합니다.

`AdvancedCompanionRecipe`는 모양 없는 조합을 검증하고 각 재료를 한 번 소비하며 저장된 동료 데이터를 유지합니다. 특화는 새 직업을 대기로 전환하되 생명력·식별자·가방·장비를 버리지 않습니다. `FriendlySlimeItem.fromSlime`은 개체의 선택 결과를 사용하여 상위종도 자신의 등록 아이템으로 회수합니다. 스키마 버전은 1이며 프로토콜 16은 같은 버전의 클라이언트와 서버를 요구합니다.

낚시는 바닐라 어획 목록과 낚시 바늘 문맥을 사용하며 열린 수면 보물 조건·바다의 행운·미끼·Forge 낚시 이벤트·기본 내구도·내구성·어획 경험치 수선을 적용합니다. 탐색량을 틱에 나누고 로드된 지형을 확인합니다. 가방에 넣지 못한 어획물은 별도로 직렬화하여 보존합니다. 실제 작업 시간으로 5분 동안 어획하지 못하면 다른 물가를 탐색합니다. 보류 중인 어획물·낚싯대 부재·기력 회복 휴식 중에는 이 시간이 흐르지 않습니다.

풍요는 치료·부활을 상속하고 환자 탐색 이후 보조 성장 동작을 수행합니다. 바닐라 뼛가루 대상·확률과 Forge 뼛가루 훅을 사용하고 지형 변경 전에 명령과 소유권을 다시 확인합니다. 뼛가루 재고는 필요하지 않습니다. 두 치유 계열 모두 탐지 배율 2를 반환하며, 성장은 나무 생성에 필요한 주변 지형이 로드되어 있어야 합니다.

터널은 채굴 장비와 가방을 상속하되 청크 굴착 목표·청크 전용 경로·청크 이동 제한·청크 수원 재생 방지 등록을 사용하지 않습니다. 수평 3×3 단면을 비우고 설치 가능한 테두리를 가방 자재로 채웁니다. 테두리 견본은 동기화된 한 칸의 샘플이며 메뉴 클릭은 커서 종류만 복사합니다. 추출·Shift 이동·숫자 키 교환·복제·버리기로 견본을 실제 재고로 바꿀 수 없습니다. 견본이나 방향을 바꾸면 대기합니다. `MATERIAL_SUPPLY`는 기존의 같은 주인 또는 상호 공동 소유 물류 거래와 최대 64개 보급 한도를 사용합니다. 파괴 전에 공동 채굴 계단 보호도 확인합니다.

드래곤은 전투의 검·방패·갑옷·필터·화물·물류를 상속하고 로드된 지형의 비행 경로를 사용합니다. 지정 화염은 근접 공격과 같은 권한을 적용하며 지형에 불을 붙이지 않습니다. 작업 속도는 간격을 바꿉니다. 처치 전리품 표식으로 자기 전리품을 수거하고 실행 상태를 활동으로 유지한 채 수거를 요청합니다. 가방 포화는 전투 중단 사유가 아닙니다.

냥냥은 활성·자유 이동 상태를 독립적으로 동기화하고 저장합니다. 크리퍼에는 고양이와 같은 6블록 거리·속도의 바닐라 `AvoidEntityGoal`을 추가하며 활성화된 길들인 냥냥만 회피 대상으로 삼습니다. 대기 중에도 회피 기능을 사용할 수 있습니다. 자유 이동은 주인 따라오기와 별도로 이동을 점유하고 로드된 경로를 사용합니다.

`SlimeToolExperience`는 작업 경험치로 수선을 적용한 뒤 남은 경험치 구슬을 생성합니다. 작업 스택은 기본 내구성 마모와 Forge의 수리 배율을 사용하고, 사용 경험치는 바닐라의 정수 내구도 환산을 따릅니다. 경험치 없는 작업이나 이미 부러진 도구는 수선하지 않습니다. 풍요는 틱당 제한된 팔레트 탐색을 끝낸 뒤 대상을 확정하고 풀밭보다 작물·묘목을 우선하여 먼저 조회된 구역이 가까운 작물의 작업을 가로막지 않게 합니다.

터널 수영은 작업 높이를 유지하고 단면 정리·휴식·보급 대기 중 수평 이동을 중지합니다. 저장되는 9비트 `TunnelDrainedFluidMask`가 현재 단면에서 비운 칸을 기록하여 다시 흘러드는 물을 반복해서 제거하지 않으며 새 수원은 계속 제거합니다. 다음 단면으로 전진하거나 기준점을 재설정하면 기록을 지웁니다. 유체 변경은 블록 스냅샷과 기본 설치 보호 이벤트를 사용하고, 반영 전에 현재 명령과 양동이를 재검증합니다. 접근 실패는 게임 틱마다 한 번 계산하며 400틱 동안 거리가 줄지 않으면 `UNREACHABLE`을 표시합니다. 이 중단 상태는 회수 후에도 유지합니다.

기본 배회는 지상 동료와 비행 동료 모두의 대기 명령을 따릅니다. 드래곤 이동 제어는 대기 명령 시 이동 목표와 속도를 지웁니다. 냥냥의 클라이언트 자유 이동 표시는 서버 전용 대기 필드 대신 동기화된 앉은 자세를 사용합니다. 테두리 견본은 사본을 반환하고 다른 칸에서 시작한 같은 아이템 모두 모으기를 포함한 일반 슬롯 추출을 거부합니다.

직업 회귀 검사는 모양 없는 조합·원본 장비와 식별자·최초 대기·어획 목록과 열린 수면·수선·보류 어획물·5분 뒤 이동·성장 우선순위와 취소·터널 형태와 설치 보호·양동이와 자재 보급·기본 기력의 침수 구역 이동·드래곤 비행과 브레스 대상 필터·바닐라 크리퍼 회피·전투 화물을 확인합니다. 도구 등급과 파괴 취소 검증은 독립된 굴착 청크를 사용합니다. 취소 검사는 대상 바로 위에서 시작하여 실제 기본 이벤트 취소와 함께 지형·장비·활동량 보존을 요구합니다. 클라이언트 검사는 직업 외형·문장·슬롯 구성 동기화·방향과 견본 변경·냥냥의 독립 명령을 확인합니다.

`MeowSlime`의 엔티티·소환 아이템·조합 직렬화기는 `meow_slime`을 사용하며, 활성·자유 이동 상태는 `MeowActive`·`MeowRoaming`으로 저장합니다. 이 이름만 지원하며 이전 이름의 등록 별칭이나 필드 변환은 제공하지 않습니다. 저장 스키마는 1, 네트워크 프로토콜은 16을 유지합니다.

## 광원·지휘·텔레포트

`GlowSlime`은 횃불 밝기의 보이지 않는 임시 `SlimeLightBlock`을 사용합니다. 블록 엔티티는 개체별 광원 유지 시간과 반딧불 만료 시각을 따로 기록합니다. 한 광원이 이동하거나 꺼져도 다른 광원은 유지하고, 반딧불이 끝나면 남은 일반 광원에서 파티클을 제거합니다. 광원은 공기에만 생기며 충돌·수집이 없고 다른 블록으로 덮을 수 있습니다. 청크에 저장한 만료 시각까지만 유지하며 유체나 고체 블록을 덮지 않습니다. 반딧불은 기본 glow 스프라이트와 자체 발광 렌더링을 사용합니다.

`CompanionRegistry`는 오버월드 `SavedData`에 식별자·원래 주인·종류·이름·차원·위치·생명력·명령·실행 상태·중단 원인·보관 상태·정규화한 태그의 마지막 기록을 저장합니다. 로드된 개체는 UUID별로 갱신 시점을 분산합니다. 진입·이탈·인벤토리 관찰·망가짐·망가진 블록 발견을 통해 소환·아이템·망가짐·제거를 구분합니다. 알려진 소환 개체의 기록은 복사 아이템 관찰로 덮지 않습니다. 과거에 관찰하지 못한 개체는 로드할 때 발견하며 보관 아이템 위치는 마지막 관찰값입니다.

원래 주인별로 공동 소유자·적대 대상 집합의 크기를 제한합니다. 위임된 관리는 공통 서버 권한 검사로 처리하며, 클라이언트 상호작용용 권한과 선택한 따라오기 주인은 엔티티 데이터로 동기화합니다. 관계 설정은 원래 소유자 UUID를 바꾸거나 가상 플레이어의 월드 보호를 우회하지 않습니다. 따라오기는 생존 중이며 관전자가 아닌 가능한 주인을 선택하고, 원래 주인의 팀 동맹은 따라오기 대상과 별도로 유지합니다. 전투는 지정한 적대 플레이어를 적대 대상으로 분류하되 PvP·팀·크리에이티브 보호를 유지합니다. 위임 권한은 관리·보호·탑승에 적용합니다. 원래 주인이 다른 동료 사이의 자동 운반·감시·치유·표시된 물품 수거는 원래 주인끼리 서로 위임해야 허용합니다. 일방적인 지정으로 상대의 보관함에 접근할 수 없도록 합니다.

`CommanderMenu`는 원래 주인에 한정한 6행 페이지와 길이를 제한한 문자열을 전송합니다. 클라이언트가 임의의 주인을 선택할 수 없으며 메뉴 식별자·거리·생존·위임 권한과 관계 변경 주체를 서버에서 재검사합니다. 집합은 기력 25로 해당 태그의 소환 기록을 대기열에 넣습니다. 지휘 슬라임은 원본 청크를 한 번에 하나만 유지하고 최대 100틱을 기다립니다. 도착할 로드 구역의 안전성을 검사하며 보관·사망·탑승 상태는 제외합니다. 청크가 바뀌면 채굴이 재개될 수 있으므로 이동 후 소환 처리 훅의 전후에 모두 대기시킵니다. 재시작 시 임시 집합 티켓을 제거하고 회수 시 대기열을 취소합니다.

지휘 슬라임의 소환 수는 저장된 공동 소유 그래프의 방향을 무시한 연결 집단으로 계산하며 관리 권한·상호 협업 권한과 분리합니다. 월드 기록은 로드되지 않은 청크와 다른 차원을 포함하고 보관·망가짐·제거 기록은 한도를 쓰지 않습니다. `FriendlySlimeItem`은 새 소환·복원·부활의 콜백 전에 집단의 한 자리를 예약하고 삽입 전에 후보를 다시 확인하며 모든 종료 경로에서 예약을 해제합니다. 보관 데이터는 원래 주인을 기준으로 합니다. 관계 변경은 소환 중인 예약도 포함해 지휘 슬라임이 있는 두 집단의 병합을 거절합니다. 예약은 저장하지 않으며 기존 기록의 스키마 1을 유지합니다. 이전 저장의 중복 지휘 슬라임은 삭제하지 않고 추가 소환을 제한합니다. `CommanderSlime.setWaiting(true)`는 진행 중인 집합과 임시 원본 청크 유지도 해제하며, 텔레포트가 거부되면 원래 명령을 보존합니다.

동료 목록은 저장된 종류에 맞춰 문구를 선택합니다. 풍요의 HEAL은 풍요 명령으로, 벌목의 SEEDS_MISSING은 묘목 부족으로 표시합니다. 저장된 명령·원인 식별자는 바꾸지 않습니다.

`EnderSlime`은 고정 중 엔티티 UUID로 영속 Forge 청크 티켓을 유지합니다. 저장된 기록으로 티켓을 검증하고 오래되거나 차원이 다른 티켓과 임시 집합 티켓을 제거합니다. 따라오기는 고정을 해제하고 회수·망가짐은 월드의 청크 티켓을 해제합니다. 아이템에 보존한 고정 상태는 다시 소환한 위치에 맞춥니다. `enderAnchorsPerOwner`의 기본 한도는 8입니다. 고정 개체를 복원하기 전에 남은 거점 수를 확인하고, 한도가 찼으면 아이템이나 망가진 블록을 보존합니다. 재시작 후 첫 틱 전에도 청크 티켓을 해제할 수 있습니다. 텔레포터는 목적지 UUID와 원래 주인을 저장하고 현재 위임 권한, 살아서 고정된 목적지, 가득 찬 기력을 요구합니다. 이동 성공 시 목적지 기력을 모두 쓰고 관성·낙하 거리를 초기화하며 텔레포트·차원 이벤트를 따릅니다. 위험하거나 사용할 수 없는 목적지는 기력과 아이템을 유지합니다.

`AttentionSlime`은 고정 UUID의 이동 속도 +50% 전체 배율을 하나만 적용합니다. 특화 데이터를 읽은 뒤 배율을 복구하고 회수 시 중복 적용하지 않습니다. 자유 이동은 목적지 선택을 10틱에 한 번으로 제한하고, 주인이 멀거나 근처 지면에 접근할 수 없으면 자신의 가까운 로드된 지면을 사용합니다. 농지를 밟지 않고 실제 이동에만 성장 보상을 줍니다. 부분 진행도는 저장합니다. 스물두 종류 모두 공통 최초 대기를 사용합니다. 프로토콜 16은 길이를 제한한 목록 행동과 클라이언트 목록을 추가하고, 저장 스키마 1은 새 필드가 없는 데이터와의 호환성을 유지합니다.

`CompanionBase`는 친근한·관심 슬라임의 대체 재료 판정과 특화 데이터 복사를 공통 처리합니다. 복사한 데이터에서 관심 전용 NBT와 고정 UUID의 속도 배율만 제거하고 속성 기본값·강화 단계·개체 정보·공통 성장 기록은 보존합니다. 조합 미리보기는 입력 아이템을 바꾸지 않습니다. 직접 특화 16종에 같은 처리를 적용하며 상위 직업은 기존 재료를 유지하고 관심 슬라임 자체는 대체 재료를 받지 않습니다. JEI도 실제 조합과 같은 대체 재료를 표시합니다.

## 작업 미리보기 스냅샷과 경고 전달

`SlimeWorkArea`는 직업별 접근자로 읽기 전용 스냅샷을 만들며, 엔티티 직렬화나 농지 조사 진행을 호출하지 않습니다. 검증된 상자·구형 범위를 최대 여덟 개까지 서버→클라이언트 `WorkAreaPacket`으로 보냅니다. 서버는 탐색기 소지·관리 권한·같은 차원·생존·관전자 여부·8블록 거리를 검사합니다. 클라이언트는 엔티티 ID와 UUID를 함께 확인하고 도구·개체·차원 변경이나 만료 시 해제합니다. 윤곽은 깊이 버퍼를 쓰지 않으며, 실수 정밀도를 유지하도록 카메라 상대 좌표로 바꾼 뒤 float로 변환합니다. 요청은 작업 명령을 바꾸거나 청크를 불러오지 않습니다. 채굴 미리보기는 실제 채굴장 초기화와 시작 바닥 높이 계산을 공유하여 월드 최저·최고 높이에서도 일치합니다. 작업 중인 농사·벌목은 재배치 후에도 등록된 중심을 사용하여 이동에 따라 표시 구역이 바뀌지 않으며, 대기 중인 농사는 다음 조사 위치를 미리 보여 줍니다.

`SlimeWorkWarning`은 종류·이름과 공통 중단 원인을 번역합니다. 채굴의 곡괭이·삽 요구를 구분하며 벌목 묘목과 농사 씨앗도 분리합니다. 낚시는 적합한 물가를 찾지 못한 경우와 이동 실패를 구분하며, 보관함 안내는 상자와 창고를 모두 포함합니다. 자동 파발 신호가 실제로 생성된 뒤 현재 중단 상태와 협력 권한을 다시 확인하고 관리 가능한 접속자에게 메시지를 보냅니다. 기존 작업자별 신호 재사용 간격으로 채팅도 제한합니다. 월드 저장은 명령을 유지하며 아이템 재배치·부활은 대기로 전환합니다. 네트워크 프로토콜 16은 같은 빌드의 서버·클라이언트를 요구하며 데이터 스키마 1은 유지합니다.

## The Slimic

`ModWorldBlocks`는 건축 54종과 장식 32종의 공통 목록을 관리합니다. 별도 블록·아이템 지연 등록부를 사용해 월드 자재와 동료 탭을 분리합니다. 모델은 Forge 렌더 유형과 색상 인덱스를 사용하며, 흙과 건축 형태는 바닐라 도구·설치 동작을 따릅니다.

`slimic:the_slimic`은 고정 `slimic:damp_plains` 바이옴과 오버월드 노이즈 라우터, 현지 표면 규칙, 바닐라 광물·동굴, 범위가 제한된 지형·식생·폐허 생성 기능을 사용합니다. 바닐라 슬라임 생성 조건의 추가분은 이 차원과 바이옴에만 적용됩니다. 유적 전리품에는 번역된 기록책이 포함됩니다.

`SlimicPortalShape`는 바닐라 슬라임 블록으로 네더 차원문 크기를 검증합니다. `SlimicPortalTravel`은 활성화, Forge 설치 이벤트와 롤백, 안전한 출구, 일반 차원 이벤트, 재이동 대기시간과 대기 도착을 처리합니다. 차원별 `slimic_portals` 저장 데이터로 출구를 찾고, 사용할 때마다 실제 틀을 검증합니다. 차원문 아이템을 만들거나 기존 네더·엔드 차원문을 변경하지 않습니다. 동료 데이터는 일반 엔티티 저장·불러오기 형식을 계속 사용합니다.

동료의 차원문 이동은 목적지 사본의 삽입과 검증을 마친 뒤 원본을 제거합니다. 생성이 거부되거나 원본 상태가 바뀌면 사본을 버리고 원본을 보존하며, 제거 훅으로 출발지의 조명·집합 티켓·정박 티켓을 해제합니다. 플레이어는 안전한 도착 지점을 확정한 뒤 일반 이동 API를 사용합니다. 이동 범위에만 등록하는 최종 우선순위 차원 이벤트 검사로 리스폰 패킷 전송이나 원본 제거 전에 권한과 도착 지점을 재검증합니다. 슬라임 차원문과 엔더 이동이 이 플레이어 검사를 공유합니다.

월드 GameTest는 틀 크기, 보호 이벤트 롤백, 아이템 사용, 출구 저장, 모든 동료 직업, 도구, 드롭과 물 머금기를 검증합니다. 클라이언트 검사는 모델, 색상, 분리된 크리에이티브 탭, 차원 이동, 기록 번역과 한·영 가이드북 렌더링을 포함합니다. [The Slimic 안내](THE_SLIMIC.kr.md)를 참고하세요.
