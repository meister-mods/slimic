# 개발 가이드

[English](DEVELOPMENT.md) | 한국어 · [프로젝트 개요](../README.kr.md)

## 빌드 환경

JDK 17을 사용합니다. Minecraft 1.20.1, Forge 47.4.10을 대상으로 하며 Gradle 8.8 wrapper를 사용합니다.

```bash
./gradlew build
```

Windows에서는 `./gradlew` 대신 `.\gradlew.bat`를 사용합니다.

실행용 파일은 `build/libs/slimic-1.20.1-<버전>.jar`입니다. `-sources.jar`는 개발용 산출물입니다.

## 개발 명령

| 명령 | 용도 |
| --- | --- |
| `./gradlew runClient` | 개발용 클라이언트를 실행합니다. |
| `./gradlew runServer` | 로컬 개발 서버를 실행합니다. |
| `./gradlew runGameTestServer` | 전용 Forge GameTest 서버를 실행합니다. |
| `./gradlew runData` | 설정된 데이터 생성기를 실행합니다. |

GameTest는 일반 개발 월드인 `run`과 분리된 `build/game-test-server`에서 실행됩니다. 테스트 소스와 구조는 `src/gameTest`에 두며 배포용 산출물에 포함하지 않습니다. 빌드는 테스트 코드를 컴파일하고, `runGameTestServer`가 실제 테스트를 실행합니다.

## 소스 구조

- `src/main/java`: 모드 진입점, 등록 코드, 슬라임 동작, 아이템 상호작용, 클라이언트 렌더링
- `src/main/resources`: 메타데이터, 텍스처, 번역, 조합법, 전리품 정의
- `src/generated/resources`: 필요한 경우 생성하는 배포용 리소스
- `src/gameTest`: 개발 전용 테스트 모드, 테스트 코드, 구조
- `docs`: 한글·영문 상세 게임플레이 및 개발 문서

각 README에는 프로젝트 개요와 문서 링크만 둡니다. 상세 가이드는 한글·영문 쌍으로 함께 관리합니다.

`src/main/resources`에는 실제 모드에서 사용하는 에셋만 포함합니다. 참고 자료와 검증 산출물은 배포 리소스와 분리합니다.

## 버전과 변경 관리

초기 개발 버전은 `0.1.x` 범위에서 패치 단위로 배포합니다. `gradle.properties`의 `mod_version`과 [변경 기록](../CHANGELOG.md)을 함께 갱신하며, 빌드에서 해당 변경 기록의 존재를 확인합니다.

배포 버전을 바꿀 때 개발 전용 테스트 모드의 버전도 맞춥니다.

## 슬라임 회수 데이터

회수 아이템의 `SlimeData`에 Forge 영구 데이터와 capability를 포함한 슬라임의 직렬화 상태 전체를 보관합니다. 새 영구 특성은 엔티티의 표준 저장·불러오기 훅을 사용해야 회수 과정에서도 자동으로 보존됩니다.

복원 시 원래 UUID와 소유권을 유지합니다. 새 소환 위치에 맞춰 좌표, 이동 속도와 낙하 거리를 대체하며, 끈과 탑승 관계는 복원하지 않습니다. 같은 UUID의 개체가 이미 로드되어 있으면 그 저장 아이템의 재소환을 막습니다.

회수 아이템의 겹침 제한은 1개입니다. 크리에이티브의 기본 아이템 수량 복원 경로에서도 회수 아이템은 재소환 시 소모합니다. 새로 제작한 아이템은 기존처럼 크리에이티브에서 반복 사용할 수 있습니다.

## 검증

변경을 마무리하기 전에 모든 Java 소스에 Google Java Format을 적용합니다.

게임플레이를 변경한 뒤에는 `build`와 `runGameTestServer`를 실행합니다. 조합법, 기본 소환, 회수·재소환, 생명력과 다른 특성, 소유권, 가득 찬 인벤토리, 막힌 위치, 크리에이티브 사용, 저장, 추종과 사망 동작을 검증합니다.

테스트 구조는 마커보다 한 칸 위에 배치되므로 구조의 바닥은 상대 Y=1입니다. 테스트용 구조는 배포용 에셋과 분리해 유지합니다.
